Programação com SocketsSocket programming with UDP and TCP

O objetivo: construir aplicações cliente-servidor que comunicam através de sockets — a porta entre o processo da aplicação e o protocolo de transporte extremo-a-extremo.

4.0.1Dois tipos de socket, dois serviços

UDP · SOCK_DGRAM

Datagramas não fiáveis.

TCP · SOCK_STREAM

Stream de bytes fiável e ordenado.

4.0.2A aplicação de exemplo

  1. O cliente lê uma linha de texto do teclado e envia-a ao servidor.
  2. O servidor recebe os dados e converte os caracteres para maiúsculas.
  3. O servidor envia os dados modificados ao cliente.
  4. O cliente recebe-os e mostra a linha no ecrã.

A mesma aplicação vai ser escrita duas vezes — com UDP e com TCP — para se ver a diferença.

⌁Mapa do tema

Baseado nas aulas de ESR (Application Layer — socket programming) e no livro de Kurose e Ross. O código está em Python 3. Caixas e etiquetas complemento vão além da matéria dada na aula.

Sockets UDPSocket programming with UDP

Com UDP não há "ligação" entre cliente e servidor.

  • Sem handshake antes de enviar dados.
  • O emissor junta explicitamente o endereço IP e a porta de destino a cada pacote.
  • O recetor extrai do pacote recebido o IP e a porta do emissor (para lhe poder responder).
  • Os dados transmitidos podem perder-se ou chegar fora de ordem.

Do ponto de vista da aplicação, o UDP fornece transferência não fiável de grupos de bytes ("datagramas") entre cliente e servidor.

4.1.1A interação

Servidor
  1. Cria o socket e associa-o à porta x (bind).
  2. Lê um datagrama do socket.
  3. Escreve a resposta no socket, indicando o endereço e a porta do cliente.
  4. Volta a 2.
Cliente
  1. Cria o socket.
  2. Cria um datagrama com o IP do servidor e a porta x e envia-o.
  3. Lê a resposta do socket.
  4. Fecha o socket.

4.1.2O código

from socket import *

serverName = 'hostname'
serverPort = 12000
clientSocket = socket(AF_INET, SOCK_DGRAM)    # socket UDP

message = input('Input lowercase sentence: ')
clientSocket.sendto(message.encode(), (serverName, serverPort))

modifiedMessage, serverAddress = clientSocket.recvfrom(2048)
print(modifiedMessage.decode())
clientSocket.close()
from socket import *

serverPort = 12000
serverSocket = socket(AF_INET, SOCK_DGRAM)
serverSocket.bind(('', serverPort))            # porta 12000
print('The server is ready to receive')

while True:
    message, clientAddress = serverSocket.recvfrom(2048)
    modifiedMessage = message.decode().upper()
    serverSocket.sendto(modifiedMessage.encode(), clientAddress)
  • sendto(dados, (host, porta)): cada envio leva o destino.
  • recvfrom(2048): devolve os dados (até 2048 bytes) e o endereço de quem os enviou.
  • Um só socket no servidor atende todos os clientes.
  • encode()/decode(): os sockets transportam bytes, não texto.

Sockets TCPSocket programming with TCP

Com TCP, o cliente tem de contactar o servidor primeiro e estabelecer uma ligação.

  • O processo servidor já tem de estar a correr e ter criado um socket — a "porta" — que dá as boas-vindas aos clientes (welcoming socket).
  • O cliente contacta o servidor criando um socket TCP e indicando o IP e a porta do processo servidor. Ao criar o socket, o TCP do cliente estabelece a ligação com o TCP do servidor.
  • Quando é contactado, o servidor TCP cria um socket novo para comunicar com aquele cliente em particular. Assim pode falar com vários clientes; as portas de origem distinguem-nos.

Do ponto de vista da aplicação, o TCP fornece uma transferência fiável e ordenada de um stream de bytes — um "tubo" — entre cliente e servidor.

4.2.1A interação

Servidor
  1. Cria o socket de boas-vindas na porta x.
  2. Espera por um pedido de ligação: accept() devolve um socket novo, connectionSocket.
  3. Lê o pedido do connectionSocket.
  4. Escreve a resposta no connectionSocket.
  5. Fecha o connectionSocket (o de boas-vindas continua aberto).
Cliente
  1. Cria o socket e liga-se ao host e à porta x (estabelecimento da ligação TCP).
  2. Envia o pedido.
  3. Lê a resposta.
  4. Fecha o socket.

4.2.2O código

from socket import *

serverName = 'servername'
serverPort = 12000
clientSocket = socket(AF_INET, SOCK_STREAM)    # socket TCP
clientSocket.connect((serverName, serverPort)) # estabelece a ligação

sentence = input('Input lowercase sentence: ')
clientSocket.send(sentence.encode())           # sem indicar o destino

modifiedSentence = clientSocket.recv(1024)
print('From Server:', modifiedSentence.decode())
clientSocket.close()
from socket import *

serverPort = 12000
serverSocket = socket(AF_INET, SOCK_STREAM)
serverSocket.bind(('', serverPort))
serverSocket.listen(1)                         # socket de boas-vindas
print('The server is ready to receive')

while True:
    connectionSocket, addr = serverSocket.accept()   # socket novo por cliente
    sentence = connectionSocket.recv(1024).decode()
    capitalizedSentence = sentence.upper()
    connectionSocket.send(capitalizedSentence.encode())
    connectionSocket.close()                   # fecha só a ligação a este cliente

UDP vs. TCP no códigoComparison

As diferenças entre os dois programas refletem diretamente as diferenças entre os dois serviços.

Tipo de socketSOCK_DGRAMSOCK_STREAM
LigaçãoNenhumaconnect() no cliente; listen() + accept() no servidor
Enviarsendto(dados, endereço) — destino em cada enviosend(dados) — o destino é o da ligação
Receberrecvfrom() devolve dados e endereçorecv() devolve só os dados
Sockets no servidorUm só, para todos os clientesUm de boas-vindas + um por ligação
GarantiasPodem perder-se ou trocar de ordemFiável e ordenado
UnidadeDatagramas (mensagens com fronteiras)Stream de bytes (sem fronteiras)
Armadilha do stream de bytes

No TCP não há fronteiras entre mensagens: dois send() seguidos podem chegar num só recv(), e uma mensagem grande pode chegar partida em vários. Em aplicações reais é preciso delimitar as mensagens (ex.: terminá-las com \n ou indicar o tamanho no início). complemento

Complemento · servir vários clientes ao mesmo tempo

O servidor TCP de exemplo atende um cliente de cada vez: enquanto trata de um, os outros esperam no accept(). Na prática usa-se uma thread (ou processo) por ligação, ou I/O assíncrono.

Σ.2Perguntas de escolha múltipla

Num cliente UDP, porque é que se usa sendto e não send?

Sem ligação estabelecida, o socket não sabe para onde enviar.

O que devolve accept() num servidor TCP?

O socket de boas-vindas continua a aceitar ligações; cada cliente tem o seu connectionSocket.

Quantos sockets usa o servidor UDP do exemplo para atender 10 clientes?

Em UDP um só socket recebe de todos; o recvfrom diz de quem veio cada datagrama.

E o servidor TCP, para 10 clientes ligados ao mesmo tempo?

Um socket de boas-vindas + um por ligação.

Que tipo de socket dá acesso direto a protocolos como o ICMP?

Os sockets raw dão acesso a camadas mais baixas, sem o serviço de transporte.

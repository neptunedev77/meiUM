Feature EngineeringFeature Engineering

Os dados reais raramente chegam prontos: há valores em falta, colunas inúteis, texto, datas. Feature engineering é o trabalho de os transformar em features numéricas, limpas e informativas — muitas vezes é isto, mais do que a escolha do modelo, que decide o resultado.

5.0.1A lista de verificação

  1. Remover valores em falta, outliers e entradas ou features desnecessárias.
  2. Verificar e imputar valores nulos.
  3. Verificar o desequilíbrio das classes.
  4. Reindexar e reformatar os dados: texto → números, datas → componentes úteis.

⌁Mapa do tema

Exemplo usado

Um registo de incidentes de trânsito numa cidade, com uma linha por hora: data, nome da cidade, luminosidade (LIGHT, DARK…), estradas afetadas, condições meteorológicas e o nível de incidentes (None, Low, Medium, High, Very_High), que é o que queremos prever. O código usa uma versão pequena destes dados, criada no próprio código.

import pandas as pd, numpy as np

df = pd.DataFrame({
    'data': ['2021-03-12 15:00', '2021-09-29 09:00', '2021-06-13 11:00',
             '2021-12-07 23:00', '2021-12-05 05:00', '2021-01-22 09:00'],
    'cidade': ['Guimarães'] * 6,
    'luminosidade': ['LIGHT', 'LIGHT', 'LIGHT', 'DARK', 'DARK', 'LOW_LIGHT'],
    'temperatura': [14.0, 15.0, np.nan, 9.0, 8.0, 8.0],
    'estradas': ['N101', None, 'N101,N105', None, None, 'N206'],
    'precipitacao': [0.0] * 6,
    'incidentes': ['Low', 'Very_High', 'High', 'Medium', 'None', 'Low'],
})

Baseado nas aulas de DAA (Feature Engineering). Caixas e etiquetas complemento vão além da matéria dada na aula.

Valores em faltaDealing with Missing Values

A maioria dos modelos não aceita valores em falta (NaN). Primeiro deteta-se onde estão; depois decide-se, coluna a coluna, o que fazer.

5.1.1Detetar

df.isnull().sum()       # temperatura: 1, estradas: 3, restantes: 0
sns.heatmap(df.isnull(), cbar=False, cmap='viridis')   # cada traço é um valor em falta
df[df['estradas'].isnull()]                            # ver as linhas afetadas

5.1.2As opções

Uma boa prática é experimentar em cópias (df1 = df.copy(), df2 = df.copy()) e comparar antes de decidir.

No exemplo, a coluna estradas (lista de estradas afetadas, em texto) não acrescenta valor ao objetivo e tem metade dos valores em falta: remove-se. A temperatura em falta preenche-se com a mediana (9.0).

Armadilha: "None" lido como valor em falta

Por omissão, pd.read_csv converte o texto "None" (e também "NA", "null", "n/a"…) em NaN. Se "None" for uma categoria legítima — como o nível de incidentes "nenhum" — a classe desaparece silenciosamente e parece haver milhares de valores em falta no target. Solução: pd.read_csv(f, keep_default_na=False, na_values=['']). complemento

Colunas constantes e classes desequilibradasDealing with Unique Values

Uma feature que tem sempre o mesmo valor não ajuda a distinguir nada. E um target com classes muito desproporcionadas muda a forma como se treina e avalia.

5.2.1Colunas com um só valor

df.nunique()      # cidade: 1, precipitacao: 1, luminosidade: 3, incidentes: 5, data: 6 …

constantes = [c for c in df.columns if df[c].nunique() == 1]   # ['cidade', 'precipitacao']
df = df.drop(columns=constantes)

Todos os registos são da mesma cidade, e a precipitação é 0 em todas as linhas. Ambas são removidas: não dão ao modelo nenhuma informação para separar as classes.

Complemento · o contrário também é suspeito

Uma coluna com um valor diferente em cada linha (como um ID ou a data-hora completa) também não generaliza: o modelo pode memorizá-la. As datas tratam-se extraindo componentes (5.4).

5.2.2Distribuição do target

df['incidentes'].value_counts()             # quantos exemplos de cada classe
sns.barplot(x=counts.index, y=counts.values)  # ou um gráfico circular com plt.pie

Num dataset real de incidentes, uma distribuição como High 36%, Low 24%, Very_High 20%, Medium 19% é razoavelmente equilibrada. Se uma classe tivesse 1% dos exemplos, a accuracy deixaria de ser fiável (tema 2) e seria preciso olhar para precision, recall e F1 por classe — e, possivelmente, usar folds estratificados ou class_weight='balanced'. complemento

Variáveis categóricasHandling Categoric Data

Alguns modelos aceitam dados categóricos, mas a maioria (incluindo os do scikit-learn) precisa de números. Há várias formas de fazer a conversão, e a escolha muda o que o modelo "vê".

a) Substituir valoresUm dicionário que tu defines: None→0, Low→1, …, Very_High→4.df.replace(mapa) / map
b) Label encodingUm inteiro por categoria, atribuído automaticamente.LabelEncoder()
c) One-hot encodingUma coluna 0/1 por categoria.pd.get_dummies, LabelBinarizer, OneHotEncoder
d) Binary encodingO inteiro de cada categoria escrito em binário, um bit por coluna.category_encoders.BinaryEncoder

import category_encoders as ce                  # pip install category_encoders
ce.BinaryEncoder(cols=['incidentes']).fit_transform(df)
O LabelEncoder não é aleatório — é alfabético

Atribui os inteiros pela ordem alfabética das categorias: High = 0, Low = 1, Medium = 2, None = 3, Very_High = 4. Num nível ordinal isto baralha a ordem real (High fica "abaixo" de Low). O mesmo vale para o factorize, que segue a ordem de aparecimento. Para variáveis ordinais, usa um mapa explícito.

5.3.3Qual escolher

Tipo de variávelMétodo recomendadoPorquê
Ordinal (Low < Medium < High)Mapa explícitoPreserva a ordem real numa só coluna.
Nominal, poucas categorias (luminosidade)One-hotNão inventa ordem.
Nominal, muitas categorias (códigos postais)Binary encodingEvita centenas de colunas.
Target de classificaçãoLabel encoding / factorizeOs classificadores só precisam de rótulos distintos.
Complemento · árvores vs. modelos lineares

Uma árvore de decisão aguenta bem uma ordem arbitrária (pode separar "código ≤ 2" e depois "código ≤ 0"), embora precise de mais divisões. Um modelo linear não: trata o código como uma quantidade e assume que "Very_High = 4" é quatro vezes "Low = 1".

DatasHandling Dates

Uma data em texto ("2021-03-12 15:00") não diz nada a um modelo. Convertida em datetime, dá origem a várias features úteis: mês, dia, hora, dia da semana…

5.4.1Converter

df['data'] = pd.to_datetime(df['data'], format='%Y-%m-%d %H:%M', errors='coerce')
assert df['data'].isnull().sum() == 0, 'datas inválidas'   # errors='coerce' transforma datas inválidas em NaT

Indicar o format evita ambiguidades (05/06 é maio ou junho?) e acelera a conversão. Com errors='coerce', uma data impossível vira NaT em vez de dar erro — por isso se confirma a seguir que não há nenhuma.

5.4.2Extrair componentes

df['mes'] = df['data'].dt.month
df['dia'] = df['data'].dt.day
df['hora'] = df['data'].dt.hour
df['dia_semana'] = df['data'].dt.day_of_week              # 0 = segunda … 6 = domingo
df['fim_semana'] = (df['dia_semana'] >= 5).astype(int)
datamesdiahoradia_semanafim_semana

Depois de extrair, aplica-se a regra de 5.2: se o ano for sempre 2021 e os minutos sempre 0, essas componentes são constantes e removem-se. A coluna de data original também sai — o modelo usa as componentes.

5.4.3Diferenças entre datas

import datetime
hoje = datetime.datetime.today()
(hoje - df['data']).dt.days        # há quantos dias aconteceu cada registo
df['data'].dt.time                 # só a hora do dia, como objeto time

A diferença entre duas datas é um timedelta; .dt.days converte-a num número. Útil para features como "antiguidade do cliente" ou "dias desde a última compra".

Complemento · variáveis cíclicas

Para o modelo, a hora 23 e a hora 0 estão "longe" (23 unidades), mas na realidade estão seguidas. Uma solução comum é codificar com seno e cosseno: \(\sin(2\pi\cdot h/24)\) e \(\cos(2\pi\cdot h/24)\).

Relações entre featuresExploratory Data Analysis

Com tudo numérico, já se pode procurar relações entre features — e entre as features e o target — antes de escolher o modelo.

  1. Matriz de correlação (sns.heatmap(df.corr(method='pearson'))) para destacar os pares mais relacionados. Num dataset de trânsito, por exemplo: magnitude do atraso com atraso em segundos (redundantes) e humidade com luminosidade.
  2. Pairplot (sns.pairplot(df, hue='incidentes')) para ver tudo de uma vez — com muitas features, fica difícil de ler.
  3. Joint plots (sns.jointplot(x=…, y=…, data=df)) para estudar um par de cada vez: dispersão no centro e a distribuição de cada variável nas margens.
  4. Reta de regressão (sns.lmplot(x='temperatura', y='humidade', data=df)) para confirmar uma tendência — por exemplo, a humidade tende a descer quando a temperatura sobe.
Ler gráficos de variáveis codificadas

Uma variável categórica codificada (luminosidade = 1, 2, 3) aparece num gráfico de dispersão como colunas verticais de pontos. Não é uma relação contínua: é uma variável discreta. Para essas, boxplots por categoria são mais legíveis.

Daqui segue-se para a modelação: separar X (sem a data original e sem o target) e y, dividir treino/teste e treinar — o que o tema 6 faz com uma árvore de decisão.

Σ.2Armadilhas frequentes

  • read_csv lê "None", "NA" e "null" como NaN por omissão.
  • LabelEncoder ordena alfabeticamente; factorize pela ordem de aparecimento — nenhum respeita uma ordem ordinal.
  • One-hot com muitas categorias explode o número de colunas.
  • Converter datas sem format pode trocar dia e mês.
  • Remover linhas com nulos pode deitar fora uma grande parte do dataset — conta-as primeiro.

Σ.3Perguntas de escolha múltipla

Uma coluna "país" tem o valor "Portugal" em todas as linhas. O que fazer?

Com um só valor (nunique() == 1), a coluna não ajuda a distinguir nenhuma classe.

Para codificar "tamanho" com valores S, M, L, XL, o melhor é…

É ordinal: o mapa preserva a ordem real. O LabelEncoder ordenaria alfabeticamente (L, M, S, XL).

Com 6 categorias, quantas colunas gera o binary encoding?

Os inteiros 1 a 6 cabem em 3 bits (⌈log₂ 7⌉ = 3). O one-hot geraria 6 colunas.

O que faz errors='coerce' em pd.to_datetime?

As datas inválidas ficam como NaT (o "NaN" das datas); depois é preciso verificá-las e tratá-las.

Uma coluna de temperatura tem 2% de nulos e alguns outliers. A opção mais segura é…

0 é uma temperatura real e enviesaria os dados; a média é puxada pelos outliers; a mediana é robusta.

Num CSV, a classe "None" (sem incidentes) aparece como NaN depois do read_csv. Porquê?

"None" está na lista de valores em falta por omissão. Usa keep_default_na=False.

Métricas de Qualidade e Validação de ModelosQuality Metrics and Model Validation

Treinar um modelo é fácil; saber se ele é bom é que é difícil. Este tema responde a duas perguntas: como medir a qualidade de um modelo (métricas) e em que dados a medir para que o resultado seja de confiança (validação).

2.0.1Porque não basta treinar

Uma árvore de decisão treinada para distinguir tumores malignos de benignos acerta em 100% dos casos com que foi treinada. Em casos novos, acerta em 95%. O primeiro número só diz que o modelo memorizou os exemplos; o segundo é o que interessa, porque mede o desempenho em dados que o modelo nunca viu.

Accuracy nos dados de treino
1.000
Accuracy em dados novos
0.951

Daqui saem as duas ideias do tema: escolher uma métrica adequada ao problema e avaliá-la em dados que o modelo não viu.

2.0.2O fluxo base

  1. Definir o input X (as features) e o target y (o que se quer prever).
  2. Separar dados de treino e de teste (ou usar validação cruzada).
  3. Treinar o modelo (fit) só com os dados de treino.
  4. Prever (predict) os dados de teste.
  5. Avaliar: comparar as previsões com os valores reais, com a métrica certa para o tipo de problema.

⌁Mapa do tema

Exemplos usados

Os conceitos são explicados com exemplos pequenos, que dá para calcular à mão. O código usa dois datasets que vêm com o scikit-learn, por isso qualquer pessoa o pode correr sem descarregar nada:

  • load_breast_cancer — 569 tumores, 30 medições numéricas cada; prever se é maligno ou benigno (classificação).
  • load_diabetes — 442 pacientes, 10 medições; prever a progressão da doença um ano depois, um valor entre 25 e 346 (regressão).

Baseado nas aulas de DAA (Quality Metrics and Model Validation). Caixas e etiquetas complemento vão além da matéria dada na aula.

Árvores de decisãoDecision Trees

Uma árvore de decisão (Decision Tree, DT) prevê o valor de uma feature alvo através de uma sequência de perguntas. É o modelo usado neste tema para gerar previsões que depois se avaliam.

2.1.1O que é

  • É um grafo hierárquico (uma árvore).
  • Cada ramo representa uma escolha entre um conjunto de alternativas.
  • Cada folha representa o resultado: uma classe (ou, na regressão, um valor).

Exemplo: "vou almoçar fora?"

Retângulos = perguntas (nós); cápsulas = folhas (a previsão). Num modelo real as perguntas são sobre features, por exemplo "raio do tumor > 16?", e são escolhidas automaticamente a partir dos dados. Como a árvore é construída e podada fica para o tema 6.

2.1.2Classificador vs. regressor

DT Classifier · classificação

O target é uma classe.

  • Binária (duas classes): almoçar ou não; um tumor é maligno ou benigno.
  • Multiclasse (mais de duas): classificar imagens de fruta em laranja, maçã ou pera.

Avaliado com: matriz de confusão, accuracy, precision, recall, F1, ROC/AUC.

DT Regressor · regressão

O target é um valor real ou contínuo.

  • Prever o fluxo de tráfego em km/h.
  • Prever o preço de uma ação em €.
  • Prever a progressão de uma doença numa escala numérica.

Avaliado com: MAE, MSE, RMSE.

Classifica cada problema:

Decidir se vou almoçar fora.
Prever o fluxo de tráfego em km/h.
Classificar fotografias de fruta.
Detetar se um email é spam.
Prever o preço de venda de uma casa.

Treinar e preverTraining, hold-out and predictions

Antes de medir seja o que for, é preciso organizar os dados em input e target, pôr uma parte de lado para teste, treinar e prever.

2.2.1Input (X) e target (y)

Por convenção, X representa o input (as features usadas para prever) e y o target (o que queremos prever). Numa tabela, y é uma coluna e X são as restantes.

2.2.2Hold-out: separar treino e teste

Antes de treinar, põe-se de parte uma porção dos dados para testar o modelo. A divisão é feita uma única vez e o modelo é avaliado em dados que não viu durante o treino. Divisões comuns: 80/20, 75/25, 65/35.

  • random_state: a semente aleatória. Fixá-la garante que a divisão é sempre a mesma e que os resultados são reprodutíveis.

2.2.3Dados categóricos: o erro clássico

As árvores de decisão do scikit-learn só aceitam números. Se X tiver uma coluna de texto (um nome, uma cidade, "M"/"F"), o fit falha com um erro deste género:

Há três saídas: converter as categorias em números com Label Encoding ou One-Hot Encoding, ou simplesmente retirar essas colunas (o mais rápido, mas perde-se informação).

2.2.4Treinar e prever

Cria-se uma instância do modelo, treina-se com fit e obtém-se uma previsão por linha do teste com predict. Como os valores reais do teste são conhecidos (y_test), dá para comparar.

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)
y = 1 - y                      # no dataset original 1 = benigno; invertemos para 1 = maligno

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)
# X_train: (426, 30)   X_test: (143, 30)

clf = DecisionTreeClassifier(random_state=42)
clf.fit(X_train, y_train)               # treinar só com os dados de treino
predictions = clf.predict(X_test)       # array de 0/1, um por tumor do teste
Regra de ouro

O fit usa só os dados de treino. Este modelo tem accuracy 1.0 no treino e 0.951 no teste: avaliar com os dados de treino mede a capacidade de memorizar, não de generalizar.

Métricas de qualidadeQuality Metrics and Model Evaluation

As métricas servem para monitorizar e medir o desempenho de um modelo. A escolha depende do problema: classificação, regressão, séries temporais…

Classificação

Previsões certas ou erradas.

  • Matriz de confusão
  • Accuracy
  • Precision e Recall
  • ROC e AUC
  • F1 Score e Fβ Score
Regressão

Previsões mais perto ou mais longe do valor real.

  • MAE — Mean Absolute Error
  • MSE — Mean Squared Error
  • RMSE — Root Mean Squared Error

Funções do scikit-learn (todas em sklearn.metrics):

Ordem dos argumentos

Em todas: primeiro os valores reais, depois os previstos. Em métricas simétricas (accuracy, MAE) trocar não muda nada, mas em precision, recall e na matriz de confusão muda tudo.

Matriz de confusão, accuracy, precision e recallClassification Models

A matriz de confusão é uma tabela que descreve o desempenho de um classificador num conjunto de teste cujos valores reais são conhecidos. Quase todas as métricas de classificação saem dela.

2.4.1Exemplo: um teste de rastreio

Um teste de rastreio de uma doença é aplicado a 200 pessoas, das quais 50 estão doentes. "Positivo" = o teste diz que a pessoa está doente.

Real: doente (50)Real: saudável (150)
Teste: positivoTP = 40
doentes detetados		FP = 15
falsos alarmes · erro tipo I
Teste: negativoFN = 10
doentes que escaparam · erro tipo II		TN = 135
saudáveis bem identificados
  • Falso positivo (erro tipo I): o modelo diz "sim" e é "não". Ex.: dizer a um homem que está grávido.
  • Falso negativo (erro tipo II): o modelo diz "não" e é "sim". Ex.: dizer a uma grávida que não está grávida.

2.4.2Accuracy, precision e recall

Accuracy — acertos ÷ total
\[\text{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN}=\frac{40+135}{200}=0.875\]
Precision — exatidão
\[\text{Precision}=\frac{TP}{TP+FP}=\frac{40}{55}\approx 0.727\]
Recall — completude
\[\text{Recall}=\frac{TP}{TP+FN}=\frac{40}{50}=0.80\]

Precision: "dos que eu disse positivo, quantos eram?"

Medida de exatidão: a proporção de casos relevantes entre os selecionados. No exemplo, 27% dos positivos do teste são falsos alarmes. Desce quando há muitos falsos positivos.

Recall: "dos positivos que existiam, quantos apanhei?"

Medida de completude: a fração dos casos relevantes que foi encontrada. No exemplo, o teste deteta 80% dos doentes. Desce quando há muitos falsos negativos.

Cuidado com os nomes
  • Sensibilidade (sensitivity, TPR) é outro nome do recall: \(TP/(TP+FN)\).
  • Especificidade (specificity) é o "recall dos negativos": \(TN/(TN+FP) = 135/150 = 0.90\).

Há materiais que associam "sensitivity" à precision e "specificity" ao recall — está trocado.

Complemento · quando a accuracy engana

Com classes desequilibradas (ex.: 1% de fraudes), um modelo que diz sempre "não é fraude" tem 99% de accuracy e recall 0. Experimenta o cenário "Classe rara" acima. Nesses casos olha para precision, recall e F1.

Qual priorizar depende do custo de cada erro: num rastreio, um FN (doente não detetado) é grave → privilegiar o recall; num filtro de spam, um FP (email legítimo perdido) é grave → privilegiar a precision.

2.4.3No scikit-learn

Com o modelo de tumores de 2.2 (positivo = maligno):

from sklearn.metrics import confusion_matrix, accuracy_score, precision_score, recall_score

confusion_matrix(y_test, predictions)   # [[85, 4], [3, 51]]
accuracy_score(y_test, predictions)     # 0.951  = (51 + 85) / 143
precision_score(y_test, predictions)    # 0.927  = 51 / (51 + 4)
recall_score(y_test, predictions)       # 0.944  = 51 / (51 + 3)
A matriz do sklearn está "ao contrário"

Na tabela acima as linhas são a previsão. No confusion_matrix do sklearn as linhas são o valor real e as colunas a previsão, com a classe 0 primeiro:

\[\begin{bmatrix}TN & FP\\ FN & TP\end{bmatrix}=\begin{bmatrix}85 & 4\\ 3 & 51\end{bmatrix}\]

Ou seja: 51 malignos detetados, 3 malignos que escaparam, 4 falsos alarmes.

Curva ROC e AUCROC and AUC

Muitos classificadores não dão só "sim" ou "não": dão uma pontuação (ex.: probabilidade de ser spam = 0.73). O "sim/não" sai de um limiar de decisão. A curva ROC mostra o desempenho em todos os limiares de uma vez.

2.5.1O limiar de decisão

Um filtro de spam que marca como spam tudo acima de 0.5 vai apanhar mais spam se o limiar descer para 0.3 — mas também vai marcar mais emails legítimos. Baixar o limiar classifica mais itens como positivos, o que aumenta tanto os TP como os FP.

A curva ROC (Receiver Operating Characteristics) desenha, para cada limiar, a taxa de verdadeiros positivos contra a taxa de falsos positivos:

TPR (= recall) — eixo y
\[TPR=\frac{TP}{TP+FN}\]
FPR — eixo x
\[FPR=\frac{FP}{FP+TN}=1-\text{especificidade}\]

2.5.2AUC: a área debaixo da curva

A AUC (Area Under the Curve) é a área debaixo da curva ROC (pensa num integral). Em vez de medir os valores absolutos das previsões, mede quão bem elas estão ordenadas. Varia entre 0 e 1: um modelo 100% errado tem AUC = 0; um 100% certo tem AUC = 1.

Como ler a AUC

AUC = 0.5 corresponde à diagonal: o modelo não distingue as classes melhor do que o acaso. A AUC é a probabilidade de um positivo escolhido ao acaso ter pontuação maior do que um negativo escolhido ao acaso — daí "mede a ordenação". Como não depende de um limiar, é útil para comparar modelos. complemento

2.5.3No scikit-learn: usa pontuações, não classes

A curva ROC precisa das pontuações do modelo (predict_proba), não das classes finais (predict). Com só 0 e 1 há um único limiar, e a "curva" fica reduzida a um ponto ligado aos cantos.

from sklearn.metrics import roc_curve, roc_auc_score
import matplotlib.pyplot as plt

proba = clf.predict_proba(X_test)[:, 1]         # probabilidade da classe 1 (maligno)
fpr, tpr, thresholds = roc_curve(y_test, proba)
roc_auc_score(y_test, proba)

plt.plot(fpr, tpr); plt.plot([0, 1], [0, 1], '--')   # diagonal = acaso
plt.xlabel('FPR'); plt.ylabel('TPR'); plt.title('ROC curve'); plt.show()
Armadilha com árvores

Uma árvore sem limite de profundidade tem folhas "puras", por isso o predict_proba só devolve 0 ou 1 — o mesmo problema. No exemplo dos tumores a árvore completa tem um único limiar (AUC 0.950); limitada a 3 níveis (max_depth=3) dá 6 limiares e uma curva a sério (AUC 0.953). complemento

F1 e FβF1 and Fβ Scores

Precision e recall puxam em sentidos opostos. A F1 junta-as num único valor, útil para comparar modelos com uma visão mais equilibrada do desempenho.

F1 — peso igual a precision e recall
\[F_1=2\cdot\frac{\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}}\]
Fβ — o recall pesa β vezes mais
\[F_\beta=(1+\beta^2)\cdot\frac{\text{Precision}\cdot\text{Recall}}{\beta^2\cdot\text{Precision}+\text{Recall}}\]
  • Com β = 1, F1 e Fβ são equivalentes.
  • β > 1 dá mais peso ao recall (rastreio médico: F2); β < 1 dá mais peso à precision (filtro de spam: F0.5).

No exemplo do rastreio (precision 0.727, recall 0.80): \(F_1 = 2\cdot\frac{0.727\cdot 0.80}{0.727+0.80}\approx 0.762\).

Porquê média harmónica

A F1 é a média harmónica de precision e recall. Ao contrário da média aritmética, fica sempre perto do menor dos dois: com precision 1.0 e recall 0.01, a média aritmética é ≈ 0.5, mas a F1 é ≈ 0.02. Não há forma de "esconder" uma métrica má atrás de outra boa. complemento

from sklearn.metrics import f1_score, fbeta_score

f1_score(y_test, predictions)               # 0.936
fbeta_score(y_test, predictions, beta=2)    # 0.941  mais peso ao recall (0.944)
fbeta_score(y_test, predictions, beta=0.5)  # 0.931  mais peso à precision (0.927)

Métricas de regressãoMAE, MSE, RMSE

Quando o target é contínuo (preços, temperaturas, tempos), usa-se um regressor e não há previsões "certas" ou "erradas": há erros maiores ou menores. As métricas resumem o tamanho desses erros.

2.7.1As três métricas

Em todas, n é o número de observações, \(y_j\) o valor real e \(\hat{y}_j\) o valor previsto.

MAE — média dos erros absolutos
\[\text{MAE}=\frac{1}{n}\sum_{j=1}^{n}\lvert y_j-\hat{y}_j\rvert\]
MSE — média dos erros ao quadrado
\[\text{MSE}=\frac{1}{n}\sum_{j=1}^{n}(y_j-\hat{y}_j)^2\]
RMSE — raiz do MSE
\[\text{RMSE}=\sqrt{\frac{1}{n}\sum_{j=1}^{n}(y_j-\hat{y}_j)^2}\]
  • MAE: magnitude média dos erros, sem considerar a direção.
  • MSE: média dos erros ao quadrado, independentemente da direção.
  • RMSE: raiz quadrada do MSE, que devolve o erro às unidades do target.
PropriedadeMAEMSERMSE
Erro médio de previsão; quanto menor, melhor✓✓✓
Varia de 0 a ∞ e ignora a direção do erro✓✓✓
Nas unidades da variável (ex.: €)✓✗ (unidades²)✓
Dá peso relativamente alto a erros grandes✗✓✓

Por isso, MSE e RMSE são mais úteis quando erros grandes são particularmente indesejáveis.

2.7.2Exemplo: dois modelos com o mesmo MAE?

Dois modelos preveem o preço de 4 casas (em milhares de €). Os erros (real − previsto) são:

ModeloErrosMAEMSERMSE
A — erros espalhados1, −1, 3, 3252.24
B — um erro grande0, 0, 0, 102.5255

O MAE quase não muda de A para B (2 → 2.5), mas o RMSE mais do que duplica (2.24 → 5): o quadrado amplifica o erro de 10. Se um erro de 10 mil € numa casa for inaceitável, o RMSE é a métrica que o mostra.

2.7.3No scikit-learn

O fluxo é o mesmo do classificador, trocando para DecisionTreeRegressor. Com o dataset de diabetes (target entre 25 e 346, média ≈ 152):

from sklearn.datasets import load_diabetes
from sklearn.tree import DecisionTreeRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error, root_mean_squared_error

X, y = load_diabetes(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)

reg = DecisionTreeRegressor(random_state=42)
reg.fit(X_train, y_train)
predictions = reg.predict(X_test)

mean_absolute_error(y_test, predictions)       # 58.84
mean_squared_error(y_test, predictions)        # 5941.70
root_mean_squared_error(y_test, predictions)   # 77.08

Lê-se assim: em média, a previsão falha a progressão da doença por cerca de 59 pontos (MAE), e o RMSE de 77 diz que há erros grandes a pesar. Para uma escala de 25 a 346, é um modelo fraco — limitar a árvore a 4 níveis (max_depth=4, tema 6) baixa o RMSE para 59.65.

Ler MAE e RMSE juntos

O RMSE é sempre ≥ MAE. Quanto maior a distância entre eles, mais o erro está concentrado em poucos casos muito mal previstos. complemento

Validação de modelosModel Validation

É preciso confirmar que o modelo cumpre o seu objetivo, avaliando-o em dados que não conhece. O hold-out faz isso, mas de forma muito básica.

2.8.1O problema do hold-out

Vês algum problema em dividir os dados uma única vez? Pensa antes de abrir.

Ver resposta

O resultado depende de qual divisão calhou. O mesmo modelo, nos mesmos dados de tumores, com cinco sementes diferentes:

random_state01234
accuracy no teste0.9160.9650.9160.9300.909
  • Uma única divisão pode dar uma estimativa otimista ou pessimista por sorte (aqui, entre 0.909 e 0.965).
  • Os dados de teste nunca servem para treinar, e os de treino nunca são testados — desperdício, sobretudo com poucos dados.

Técnicas de validação: hold-out, cross validation, k-fold cross validation, leave-one-out cross validation, …

2.8.2Validação cruzada k-fold

O objetivo é obter uma medida precisa de como o modelo se vai comportar na prática. Divide-se o dataset em k folds (partes). Em cada execução, k − 1 folds treinam e o fold restante testa. Repete-se até todos os folds terem sido usados para teste. A métrica final é a média das k métricas:

\[E=\frac{1}{k}\sum_{i=1}^{k}E_i\]

2.8.3Quantos folds?

  • Mais folds → estimativa de erro mais precisa e com menos bias, mas maior custo computacional (treinam-se k modelos).
  • Dataset grande: um k mais pequeno pode chegar, porque cada treino já tem muitos dados.
  • Dataset pequeno: pode valer a pena o leave-one-out, para maximizar os dados de treino.
  • Na prática, k depende de N. Regra prática: k = 10.
k-fold

Normalmente k = 10. Cada observação é testada exatamente uma vez e usada para treino nas restantes k − 1 iterações.

Leave-one-out (k = N)

Caso especial: cada fold tem uma só observação. É caro (N treinos), mas é uma boa abordagem para datasets pequenos.

Complemento

Além da média, o desvio padrão das k métricas diz quão estável é o modelo entre folds.

StratifiedKFold cria folds com a mesma proporção de classes do dataset completo — importante com classes desequilibradas. O cross_val_score usa-o automaticamente em classificação.

2.8.4No scikit-learn

Classes úteis em sklearn.model_selection: train_test_split, KFold, LeaveOneOut, StratifiedKFold, GridSearchCV e RandomizedSearchCV (estas duas ficam para a afinação de hiperparâmetros).

from sklearn.model_selection import cross_val_score

clf = DecisionTreeClassifier(random_state=42)
scores = cross_val_score(clf, X, y, cv=10)       # 10 folds → 10 accuracies (sobre os 569 tumores)
print("%0.3f accuracy with a standard deviation of %0.3f" % (scores.mean(), scores.std()))
# 0.928 accuracy with a standard deviation of 0.033
from sklearn.model_selection import KFold
import numpy as np

kf = KFold(n_splits=10)
scores = []
for train, test in kf.split(X):                  # índices de treino e de teste de cada fold
    clf.fit(X[train], y[train])
    scores.append(clf.score(X[test], y[test]))   # accuracy neste fold
    print(confusion_matrix(y[test], clf.predict(X[test])))
print(np.mean(scores), np.std(scores))           # 0.937, 0.032

A versão manual dá mais controlo — por exemplo, ver a matriz de confusão de cada fold. A diferença entre 0.928 e 0.937 vem dos folds serem diferentes: o primeiro usa folds estratificados, o segundo não.

Em regressão, a métrica escolhe-se com scoring. O sklearn maximiza sempre, por isso os erros vêm com sinal negativo:

X, y = load_diabetes(return_X_y=True)
reg = DecisionTreeRegressor(max_depth=4, random_state=42)
scores = cross_val_score(reg, X, y, cv=10, scoring='neg_root_mean_squared_error')
-scores.mean(), scores.std()     # RMSE médio nos 10 folds: 64.23, desvio 5.29

Σ.2Armadilhas frequentes

  • Avaliar com os dados de treino mede memorização, não generalização.
  • Recall = sensibilidade; especificidade = TN/(TN+FP). A precision não é a sensibilidade.
  • No sklearn a matriz de confusão é [[TN, FP], [FN, TP]] (linhas = valor real).
  • ROC/AUC calculadas com classes 0/1 (predict) dão um só ponto; usa pontuações (predict_proba).
  • MSE não está nas unidades do target; RMSE e MAE estão.
  • Um único hold-out pode dar um resultado otimista ou pessimista por sorte.
  • Árvores do sklearn não aceitam texto: é preciso codificar ou retirar as colunas categóricas.

Σ.3Perguntas de escolha múltipla

Prever a temperatura máxima de amanhã em °C é um problema de…

O target é um valor contínuo → regressor e métricas como MAE/RMSE.

Num teste de uma doença, dizer a uma pessoa doente que está saudável é um…

Era positivo (doente) e foi previsto negativo → falso negativo. Para os evitar, privilegia-se o recall.

Qual destas métricas é também chamada sensibilidade?

Sensibilidade = recall = TPR = TP/(TP+FN).

TP = 30, FP = 10, FN = 20, TN = 40. Qual é a precision?

Precision = 30/(30+10) = 0.75. Recall = 30/(30+20) = 0.60; accuracy = 70/100 = 0.70.

Um modelo tem AUC = 0.5. Isto significa que…

AUC 0.5 corresponde à diagonal da ROC. AUC 0 seria "sempre errado" (e invertendo as previsões ficaria perfeito).

Precision = 1.0 e recall = 0.1. A F1 é aproximadamente…

F1 = 2·1·0.1/(1+0.1) ≈ 0.18. A média aritmética seria 0.55 — a F1 penaliza o recall baixo.

Erros de dois modelos: A = (2, 2, 2, 2), B = (0, 0, 0, 8). Qual afirmação é verdadeira?

MAE: 8/4 = 2 em ambos. RMSE A = √4 = 2; RMSE B = √(64/4) = 4. O RMSE penaliza o erro grande de B.

Com 10-fold cross validation, quantas vezes é treinado o modelo e quantas vezes cada observação é usada para teste?

Cada fold é teste exatamente uma vez; nas outras 9 iterações essa observação está no treino.

Tens um dataset com 40 observações. Que validação é mais indicada?

Com poucos dados, o LOOCV maximiza os dados de treino em cada iteração; o custo (40 treinos) é aceitável.

Σ.4Exercícios de cálculo

1. Matriz: TP = 80, FP = 20, FN = 40, TN = 860. Calcula accuracy, precision, recall e F1.

Total = 1000. Accuracy = 940/1000 = 0.94. Precision = 80/100 = 0.80. Recall = 80/120 ≈ 0.667. F1 = 2·0.8·0.667/(1.467) ≈ 0.727. A accuracy é alta porque há muitos negativos; o recall mostra que um terço dos positivos escapa.

2. O sklearn devolveu [[50, 10], [5, 35]]. Quais são TP, FP, FN e TN?

Formato [[TN, FP], [FN, TP]] → TN = 50, FP = 10, FN = 5, TP = 35. Precision = 35/45 ≈ 0.78; recall = 35/40 = 0.875.

3. Com precision = 0.6 e recall = 0.9, calcula F1 e F2.

F1 = 2·0.54/1.5 = 0.72. F2 = 5·0.54/(4·0.6 + 0.9) = 2.7/3.3 ≈ 0.818 — mais alto, porque β = 2 valoriza o recall, que é o valor mais alto.

4. Reais (10, 20, 30) e previstos (12, 18, 36). Calcula MAE, MSE e RMSE.

Erros: −2, 2, −6. MAE = (2+2+6)/3 ≈ 3.33. MSE = (4+4+36)/3 ≈ 14.67. RMSE = √14.67 ≈ 3.83.

5. Dataset de 1000 observações com 5-fold CV: quantas observações treinam e testam em cada iteração?

Cada fold tem 200. Em cada iteração: 800 treino, 200 teste; 5 modelos treinados no total.

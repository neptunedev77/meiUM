Interpretabilidade e ExplicabilidadeInterpretability and Explainability

Um modelo com 97% de accuracy ainda deixa uma pergunta em aberto: porque é que decidiu assim? Este tema trata das técnicas para responder a essa pergunta, para o modelo inteiro e para cada previsão.

8.0.1Dois conceitos próximos

Interpretabilidade · porquê

Perceber a causa da decisão do modelo: compreender o seu comportamento e o processo pelo qual chega a uma previsão.

Explicabilidade · como

Explicar o comportamento do modelo depois de treinado (post hoc), e comunicar essa explicação a quem usa o modelo: que features pesaram e como.

As duas dão transparência a decisões automáticas, o que permite confiança, responsabilização e a possibilidade de depurar o modelo quando algo corre mal. Isto conta sobretudo quando a decisão afeta pessoas: um crédito recusado, um diagnóstico, uma seleção para entrevista.

Onde entra no ciclo de vida

Depois de treinar os modelos candidatos e ao avaliá-los: além de "qual acerta mais?", pergunta-se "acerta pelas razões certas?". Um modelo que acerta por usar uma feature que não devia (um identificador, uma fuga de informação do target) só se apanha olhando para as explicações.

8.0.2O exemplo deste tema

Usamos o load_breast_cancer (569 tumores, 30 features numéricas, 1 = maligno), dividido 70/30 de forma estratificada. O modelo principal é uma Random Forest, e a pergunta é a mesma de qualquer problema de classificação: porque é que este tumor foi classificado como benigno, e que medidas pesam mais no modelo em geral?

import numpy as np, pandas as pd
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier

data = load_breast_cancer(as_frame=True)
X, y = data.data, 1 - data.target            # 1 = maligno
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

rf = RandomForestClassifier(n_estimators=100, random_state=42).fit(X_train, y_train)
rf.score(X_test, y_test)                     # 0.965

Baseado nas aulas de DAA (Interpretability and Explainability). Caixas e etiquetas complemento vão além da matéria dada na aula.

Importância das featuresFeature Importance

A importância de uma feature mede o seu contributo para o desempenho preditivo do modelo, revelando que atributos têm mais impacto nos resultados.

Serve para perceber o modelo, mas também para o melhorar: orienta a seleção de features (manter as relevantes, retirar as inúteis), o que pode aumentar a accuracy e tornar o modelo mais eficiente.

Importância nas árvores: MDIMean Decrease in Impurity (Gini importance)

Cada divisão de uma árvore reduz a impureza (Gini ou entropia). A importância MDI de uma feature é quanto essa feature reduziu a impureza, somado por todas as divisões em que foi usada e calculado em média sobre as árvores da floresta.

8.2.1No scikit-learn

É o atributo feature_importances_ do modelo treinado: fica disponível de graça, sem cálculos extra. Os valores estão normalizados e somam 1. O desvio padrão entre as árvores dá uma ideia de quanto varia.

mdi = pd.Series(rf.feature_importances_, index=X.columns).sort_values(ascending=False)
std = pd.Series(np.std([t.feature_importances_ for t in rf.estimators_], axis=0), index=X.columns)
pd.DataFrame({'mdi': mdi, 'std': std[mdi.index]}).head(5)
                        mdi    std
worst area            0.168  0.278
mean concave points   0.111  0.226
worst concave points  0.102  0.198
worst radius          0.081  0.202
worst perimeter       0.079  0.182
"Random Forest importance" e "MDI" são o mesmo número

Por vezes aparecem como se fossem dois métodos, mas no scikit-learn ambos são o feature_importances_: a importância de Gini é a redução média da impureza. O que muda é só a apresentação (com ou sem as barras de desvio padrão).

O desvio padrão é maior do que a própria média. Isso é normal numa Random Forest: cada árvore vê só uma parte das features em cada divisão, por isso uma árvore pode depender muito da área e outra quase nada.

8.2.2Limitações

  • É calculada sobre os dados de treino: mede o que a árvore usou para se ajustar, não o que ajuda a generalizar.
  • Tem um enviesamento a favor de features com muitos valores distintos (contínuas, ou categóricas com muitas categorias): têm mais pontos de corte possíveis, por isso entram em mais divisões, mesmo que por acaso.
Experiência: uma feature de puro ruído complemento

Acrescenta-se uma coluna de números aleatórios, sem qualquer relação com o target, e treina-se de novo:

rng = np.random.RandomState(0)
X_tr2 = X_train.assign(ruido=rng.randn(len(X_train)))
X_te2 = X_test.assign(ruido=rng.randn(len(X_test)))
rf2 = RandomForestClassifier(n_estimators=100, random_state=42).fit(X_tr2, y_train)
# MDI do ruído: 0.0055, 24.º lugar em 31: à frente de 7 features reais
# importância por permutação do ruído: 0.0000

A MDI dá ao ruído mais importância do que a 7 medidas reais do tumor. A importância por permutação, calculada no teste, dá-lhe exatamente zero.

Importância por permutaçãoPermutation Feature Importance

Uma ideia simples e agnóstica: se uma feature é importante, baralhar os seus valores deve estragar as previsões. Quanto mais o desempenho cai, mais importante ela é.

8.3.1O algoritmo

  1. Mede-se o desempenho do modelo já treinado num conjunto de avaliação (de preferência o de teste).
  2. Baralham-se ao acaso os valores de uma coluna. Isto quebra a sua relação com o target e mantém a distribuição da coluna.
  3. Mede-se de novo o desempenho. A queda é a importância dessa feature.
  4. Repete-se várias vezes (n_repeats) e faz-se a média, porque cada baralhamento é aleatório. Depois passa-se à feature seguinte.
Importância da feature j complemento
\[I_j = s - \frac{1}{K}\sum_{k=1}^{K} s_{k,j}\]

Aqui \(s\) é o score original e \(s_{k,j}\) o score depois da k-ésima permutação da coluna \(j\). Não é preciso treinar de novo: o modelo fica igual, só mudam os dados de entrada.

Em relação à MDI, tem duas vantagens: não favorece features com muitos valores distintos e pode ser calculada num conjunto que o modelo não viu.

8.3.2No scikit-learn

from sklearn.inspection import permutation_importance

result = permutation_importance(rf, X_test, y_test, n_repeats=10, random_state=42)
pi = pd.DataFrame({'mean': result.importances_mean, 'std': result.importances_std},
                  index=X.columns).sort_values('mean', ascending=False)

Lê-se assim: baralhar a worst area faz a accuracy descer, em média, 1.6 pontos percentuais. O topo coincide em parte com a MDI (área e pontos côncavos), mas a ordem e os valores mudam.

Metade das features com importância zero?

Aqui, 15 das 30 features têm importância ≤ 0. Não quer dizer que sejam inúteis. Este dataset tem grupos de features muito correlacionadas (raio, perímetro e área medem quase o mesmo). Quando se baralha uma delas, o modelo continua a ter as outras e quase não perde nada. A importância por permutação mede o que se perde ao tirar uma feature mantendo as restantes, por isso divide (ou anula) a importância entre features redundantes.

Custo complemento

São necessárias \(n_\text{features}\times n_\text{repeats}\) passagens de previsão: aqui, 30 × 10 = 300. A MDI é instantânea. Com modelos lentos ou muitas features, a permutação pode demorar.

SHAPSHapley Additive exPlanations

O SHAP vem da teoria dos jogos. As features são "jogadores" que cooperam para produzir a previsão, e o valor de Shapley reparte essa previsão de forma justa entre eles.

8.4.1A ideia

Cada previsão é decomposta numa soma: parte-se da previsão média do modelo e cada feature empurra para cima ou para baixo. Daí o "additive" no nome.

Propriedade aditiva
\[f(x) \;=\; \underbrace{\mathbb{E}[f(X)]}_{\text{valor base}} \;+\; \sum_{j=1}^{p} \phi_j(x)\]
  • \(\phi_j(x) > 0\): a feature \(j\) aumenta a previsão para este exemplo; \(\phi_j(x) < 0\): diminui.
  • O mesmo cálculo dá uma explicação local (os \(\phi_j\) de um exemplo) e, fazendo a média de \(|\phi_j|\) sobre muitos exemplos, uma explicação global.
  • Como reparte o efeito pela distribuição dos valores das features, e não por médias ou contagens simples, capta melhor as interações. Isso ajuda também a detetar e mitigar enviesamentos do modelo.
Valor de Shapley complemento
\[\phi_j=\sum_{S\subseteq F\setminus\{j\}}\frac{|S|!\,(p-|S|-1)!}{p!}\Big[v(S\cup\{j\})-v(S)\Big]\]

complemento Em palavras: imagina as features a "chegar" uma a uma, por todas as ordens possíveis. Em cada ordem, a feature \(j\) recebe o que acrescentou à previsão quando chegou (\(v(S\cup\{j\})-v(S)\), em que \(v(S)\) é a previsão esperada conhecendo só as features de \(S\)). O valor de Shapley é a média desse contributo sobre todas as ordens.

Porque é que o SHAP precisa de "explainers" complemento

Com \(p\) features há \(2^p\) subconjuntos: com 30 features, mais de mil milhões. Por isso o SHAP tem algoritmos próprios para cada família de modelos:

  • TreeExplainer: exato e rápido para árvores, Random Forest e XGBoost.
  • LinearExplainer: exato para modelos lineares.
  • KernelExplainer: qualquer modelo (agnóstico), por amostragem e lento.

sv = explainer(X_test)               # forma (171, 30, 2): exemplos × features × classes

Classificadores: escolher a classe

No RandomForestClassifier, os valores SHAP têm uma dimensão a mais, uma por classe. sv[i, :, 1] explica a probabilidade da classe 1. Na classe 0, os valores são simétricos.

8.4.4Feature a feature: dependência e PDP

Um gráfico de dispersão (shap.plots.scatter) põe, para uma feature, o seu valor no eixo x e o seu \(\phi\) no eixo y, com um ponto por exemplo. Mostra em que sentido e a partir de que valores a feature empurra a previsão.

shap.plots.scatter(sv[:, 'worst concave points', 1])

Aqui, a correlação entre o valor e o \(\phi\) de worst concave points é 0.86: valores baixos puxam para benigno e valores altos (acima de ≈ 0.10, a mediana) puxam para maligno. É o tipo de leitura que se faz em problemas de tabela, como "ter menos de 10 anos aumentava a probabilidade de sobreviver".

Um partial dependence plot (PDP) é uma ferramenta global: mostra como a previsão média do modelo muda quando se varia uma feature, mantendo as outras como estão nos dados.

shap.partial_dependence_plot('worst concave points', lambda d: rf.predict_proba(d)[:, 1], X_train,
                             ice=False, model_expected_value=True, feature_expected_value=True)

8.4.5Num modelo linear

Para um modelo linear com features independentes, o valor de Shapley tem uma forma fechada:

SHAP de um modelo linear complemento
\[\phi_j(x)=\beta_j\,\big(x_j-\mathbb{E}[x_j]\big)\]

O coeficiente diz quanto vale cada unidade; o desvio face à média diz quantas unidades este exemplo tem a mais ou a menos.

from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler

sc = StandardScaler().fit(X_train)
Xs_train = pd.DataFrame(sc.transform(X_train), columns=X.columns)
Xs_test  = pd.DataFrame(sc.transform(X_test),  columns=X.columns)
lr = LogisticRegression(max_iter=1000, random_state=42).fit(Xs_train, y_train)   # accuracy 0.971

lexp = shap.LinearExplainer(lr, shap.maskers.Independent(Xs_train, max_samples=len(Xs_train)))
lsv = lexp(Xs_test)
j = X.columns.get_loc('worst texture')
lsv.values[0, j]                                              # 0.5597
lr.coef_[0, j] * (Xs_test.iloc[0, j] - Xs_train.iloc[:, j].mean())   # 0.5597  ← igual
Unidades diferentes

Na regressão logística, o SHAP explica o log-odds (a saída antes da sigmoide), e não a probabilidade: o valor base é −0.348 e a soma para o tumor 0 dá −2.057, que é o decision_function. Por isso, os \(\phi\) de modelos diferentes não se comparam pelo tamanho, só pela ordem.

Regressão linear num target 0/1 complemento

Também se pode explicar uma LinearRegression treinada num target binário (sobreviveu sim/não, por exemplo), e o SHAP funciona da mesma forma. Mas, para classificar, a regressão logística é o modelo mais adequado: as previsões ficam entre 0 e 1 e os coeficientes têm uma leitura em odds.

Comparar modelos e métodos

Três modelos com accuracy quase igual podem justificar as decisões com features diferentes. Comparar as explicações é tão útil como comparar as métricas.

8.5.2Como ler isto

Porque é que os rankings diferem? Pensa primeiro, depois abre
  • Na mesma Random Forest, os três métodos concordam no essencial (área e pontos côncavos). As diferenças vêm do que cada um mede: o uso no treino (MDI), a perda no teste (permutação) e a contribuição por previsão (SHAP).
  • Entre modelos, o topo muda porque há features redundantes. Área, raio e perímetro trazem quase a mesma informação, e cada modelo "escolhe" uma delas: o modelo pode trocar uma pela outra sem perder desempenho.
  • A importância é do modelo, não do fenómeno: diz em que é que o modelo se apoia, não o que causa a malignidade.
Qual é o modelo mais interpretável?
  • A regressão logística é interpretável por natureza: cada coeficiente é o efeito de uma feature, igual para todos os exemplos, e o SHAP é só \(\beta_j(x_j-\bar x_j)\).
  • A Random Forest e o XGBoost captam interações e não-linearidades, mas são caixas negras: precisam de MDI, permutação ou SHAP para se explicarem.
  • Neste dataset, a logística tem praticamente a mesma accuracy (0.971 contra 0.965 e 0.977). Quando a diferença de desempenho é pequena, o modelo mais simples de explicar é muitas vezes a melhor escolha.

Σ.2Armadilhas frequentes

  • Importância não é causalidade. Diz em que é que o modelo se apoia, não o que causa o resultado.
  • Identificadores como features. Um PassengerId ou um número de cliente não tem significado. Se aparecer como importante numa explicação, é sinal de um problema nos dados (ordem, fuga de informação), não de um padrão real. Remove-se antes de treinar.
  • Features correlacionadas dividem a importância entre si. Na permutação, cada uma pode até parecer inútil.
  • A MDI é calculada no treino e favorece features com muitos valores distintos.
  • Escalas de SHAP diferentes (probabilidade vs. log-odds) não se comparam pelo tamanho entre modelos.
  • Num classificador, escolher a classe certa nos valores SHAP (sv[:, :, 1]).

Σ.3Perguntas de escolha múltipla

Um banco tem de explicar a um cliente porque é que o seu crédito foi recusado. Que tipo de explicação precisa?

Uma explicação local justifica uma decisão concreta; a global descreve o modelo em geral.

O que é a importância por permutação de uma feature?

Baralhar quebra a relação com o target; a queda do score mede quanto o modelo dependia dela. O modelo não é treinado de novo.

Qual é uma vantagem da importância por permutação sobre a MDI?

A MDI é calculada no treino e é enviesada para features com muitos pontos de corte. A permutação é agnóstica e mede a generalização.

Num tumor, o valor base do SHAP é 0.37 e a soma dos \(\phi\) é −0.32. Qual é a previsão do modelo?

Pela propriedade aditiva, f(x) = valor base + Σφ = 0.37 − 0.32 = 0.05.

O que significa um valor SHAP negativo para uma feature num exemplo?

O sinal do φ é o sentido do contributo face ao valor base, não o sinal do valor da feature.

Raio, perímetro e área de um tumor estão muito correlacionados. O que se espera na importância por permutação de cada um?

Ao baralhar uma feature redundante, a informação continua disponível nas outras, por isso o score quase não cai.

Numa Random Forest, a MDI dá a uma coluna de números aleatórios uma importância maior do que a algumas features reais. Porquê?

Com muitos valores distintos, há sempre algum corte que reduz a impureza por acaso no treino. No teste, essa "importância" não se mantém.

Qual destas técnicas é agnóstica do modelo?

A permutação só precisa de fazer previsões; a importância de Gini usa a estrutura interna das árvores.

Aprendizagem Não SupervisionadaUnsupervised Learning: Clustering and Autoencoders

Na aprendizagem supervisionada, cada exemplo vem com a resposta certa. Na não supervisionada, não há nada a prever: o algoritmo procura sozinho padrões e estrutura nos dados.

10.0.1Duas famílias

Clustering

Agrupar os dados por semelhança: pontos parecidos no mesmo grupo, pontos diferentes em grupos diferentes. Neste tema: K-means, K-medoids e DBSCAN.

Autoencoders

Redes neuronais que aprendem a comprimir os dados numa representação pequena e a reconstruí-los a partir dela. Servem para reduzir a dimensionalidade e para detetar anomalias.

Exemplos de uso: segmentar clientes, agrupar documentos ou genes semelhantes, encontrar transações invulgares, ou comprimir dados com muitas features em poucas.

Preparar os dados conta, e muito

Quase todos estes algoritmos assentam em distâncias, por isso as features devem estar normalizadas: sem isso, a que tiver a maior escala domina tudo (ver 10.5). Com muitas features, costuma também ajudar reduzir primeiro a dimensionalidade.

Instalar o K-medoids

O KMedoids não está no scikit-learn, mas no pacote scikit-learn-extra. Esse pacote deixou de ser mantido e muitas vezes não instala em versões recentes do Python: falha a compilar, porque não há versões pré-compiladas. A alternativa é o pacote kmedoids (pip install kmedoids), com uma API parecida. É o usado nos exemplos deste tema (ver 10.3).

⌁Mapa do tema

Baseado nas aulas de DAA (Unsupervised Learning: Clustering and Autoencoders). Caixas e etiquetas complemento vão além da matéria dada na aula.

K-means

Um método de partição: divide os dados em k grupos, cada um representado pelo seu centróide (a média dos pontos do grupo), de forma a que os pontos fiquem o mais perto possível do centro do seu grupo.

10.1.1O algoritmo

  1. Escolhem-se k centros iniciais. O scikit-learn usa k-means++, que espalha os centros iniciais pelos dados.
  2. Atribuição: cada ponto vai para o centro mais próximo.
  3. Atualização: cada centro passa a ser a média dos pontos que lhe foram atribuídos.
  4. Repete-se 2–3 até os centros deixarem de mudar.
O que o K-means minimiza: a inércia complemento
\[\sum_{i=1}^{n}\big\lVert x_i-\mu_{c(i)}\big\rVert^2\]

O resultado depende dos centros iniciais. Por isso, o n_init corre o algoritmo várias vezes e fica com a melhor solução.

10.1.2No scikit-learn

sklearn.cluster.KMeans(n_clusters=8, *, init='k-means++', n_init='auto', max_iter=300,
                       tol=0.0001, random_state=None, algorithm='lloyd')

Para ter dados com grupos conhecidos usa-se o make_blobs, que gera nuvens gaussianas isotrópicas e devolve também o grupo de cada ponto. Assim, o resultado pode ser comparado com a verdade.

from sklearn.datasets import make_blobs
from sklearn.cluster import KMeans

X, y = make_blobs(n_samples=200, n_features=2, centers=4, cluster_std=1.8, random_state=101)
kmeans = KMeans(n_clusters=4, n_init=10, random_state=42).fit(X)
kmeans.cluster_centers_     # [[-9.47 -6.56] [-0.01 2.13] [-4.14 7.95] [3.72 7.01]]
kmeans.labels_[:10]         # [2 3 1 3 3 0 3 1 3 1]
y[:10]                      # [3 2 0 2 2 1 2 0 2 0]   ← números diferentes, grupos iguais

10.1.3Os números dos clusters não significam nada

O "cluster 2" do K-means não tem nada a ver com o "grupo 2" verdadeiro: os números são arbitrários, e por isso as cores de dois gráficos não se comparam. Antes de construir uma matriz de confusão, é preciso alinhar os números, emparelhando cada cluster com o grupo com que mais se sobrepõe.

import numpy as np
from scipy.optimize import linear_sum_assignment
from sklearn.metrics import confusion_matrix, accuracy_score

def align(y_true, y_pred):                      # emparelhamento ótimo (algoritmo húngaro)
    cm = confusion_matrix(y_true, y_pred)
    rows, cols = linear_sum_assignment(-cm)
    mapping = dict(zip(cols, rows))
    return np.array([mapping[c] for c in y_pred])

y_pred = align(y, kmeans.labels_)
confusion_matrix(y, y_pred)
accuracy_score(y, y_pred)                       # 0.96
[[49  0  1  0]
 [ 0 50  0  0]
 [ 3  0 47  0]
 [ 2  0  2 46]]
Alinhar à mão vs. automaticamente complemento

Também se podem trocar os números à mão, com np.where, depois de olhar para os gráficos. Mas isso muda a cada execução. O linear_sum_assignment faz o emparelhamento que maximiza a diagonal, sempre. E métricas como o ARI (10.2) nem precisam de alinhamento.

Para classificar pontos novos, o kmeans.predict(x) atribui-os ao centro mais próximo. Em alternativa, pode treinar-se um classificador sobre os rótulos que o clustering produziu.

Avaliar clusters

Sem target não há accuracy. Há dois tipos de métricas: as que comparam com rótulos verdadeiros (quando os há, como no make_blobs) e as que só olham para a geometria dos clusters.

from sklearn import metrics

Homogeneidade, completude, V-measure, ARI e AMI não dependem dos números dados aos clusters: dão o mesmo valor com ou sem alinhamento. A silhueta é a única que se pode usar num problema real, onde não há rótulos.

Silhueta de um ponto complemento
\[s=\frac{b-a}{\max(a,b)}\]

complemento \(a\) é a distância média aos pontos do próprio cluster e \(b\) a distância média aos pontos do cluster vizinho mais próximo. Perto de 1: ponto bem colocado; perto de 0: na fronteira; negativo: provavelmente no cluster errado.

10.2.2Escolher k complemento

O K-means precisa de saber k de antemão. Sem rótulos, compara-se a solução para vários k:

k      2       3       4       5       6       7       8
inércia 3799.2  2288.1  1318.4  1133.2   990.4   883.3   770.0
silhueta 0.649   0.504   0.552   0.479   0.390   0.359   0.356
  • Método do cotovelo: a inércia desce sempre com k (com k = n chega a 0), por isso procura-se o ponto em que deixa de descer muito. Aqui é em k = 4: de 3 para 4 cai 970, de 4 para 5 só 185.
  • Silhueta: escolhe-se o k com a silhueta mais alta. Aqui ganha k = 2 (0.649), porque dois dos quatro grupos estão próximos e "juntá-los" também faz sentido geometricamente. Entre k ≥ 3, ganha k = 4.

Os critérios nem sempre concordam: escolher k é em parte uma decisão do problema (quantos segmentos de clientes fazem sentido?), e não só da matemática.

K-medoids

Também divide os dados em k grupos, mas cada grupo é representado por um medoide: um ponto real dos dados, o que tem a menor soma de distâncias aos outros pontos do grupo.

A implementação mais comum é o PAM (Partitioning Around Medoids): começa com k medoides e vai trocando um medoide por um ponto que não o é, sempre que isso reduz a soma das distâncias. É uma pesquisa gulosa, por isso pode não encontrar o ótimo global.

Forma dos clustersAmbos funcionam melhor com grupos compactos e mais ou menos esféricos, e nenhum lida bem com formas arbitrárias (para isso, ver DBSCAN)

DBSCANDensity-Based Spatial Clustering of Applications with Noise

Em vez de centros, o DBSCAN procura regiões densas (pontos próximos uns dos outros) separadas por regiões pouco densas. Encontra amostras core em zonas de alta densidade e expande os clusters a partir delas.

10.4.1Como funciona

  • Um ponto A é core se tiver, a uma distância ≤ ε, pelo menos min_samples pontos (normalmente contando com o próprio A).
  • Um cluster é formado por pontos core ligados entre si (cada um na vizinhança ε de outro) e pelos pontos que estão na vizinhança deles.
  • Os pontos que não estão perto de nenhum core ficam como ruído (rótulo -1).

complemento Os pontos de um cluster que não são core, mas estão na vizinhança de um, chamam-se pontos de fronteira (border).

Pontos fortes
  • Não é preciso saber o número de clusters
  • Deteta anomalias: o ruído são os outliers
  • Encontra clusters com qualquer forma
Pontos fracos
  • É preciso escolher e afinar ε (e min_samples)
  • Lida mal com dados esparsos e com clusters de densidades muito diferentes

10.4.2Escolher ε: o gráfico de k-distâncias

  1. Para cada ponto, calcula-se a distância ao seu k-ésimo vizinho mais próximo, com k = min_samples.
  2. Ordenam-se essas distâncias e desenham-se num gráfico.
  3. Procura-se o cotovelo, onde a curva sobe de repente: abaixo dele estão os pontos de zonas densas, acima os isolados. Esse valor é um bom ε.
from sklearn.datasets import make_moons
from sklearn.neighbors import NearestNeighbors
from sklearn.cluster import DBSCAN

X, y = make_moons(n_samples=300, noise=0.07, random_state=42)
X = np.vstack([X, np.random.RandomState(0).uniform([-1.5, -1], [2.5, 1.5], size=(12, 2))])  # + 12 pontos de ruído

dist, _ = NearestNeighbors(n_neighbors=5).fit(X).kneighbors(X)
k_dist = np.sort(dist[:, -1])           # percentis: 50% 0.089 · 90% 0.147 · 95% 0.171 · 99% 0.645
# plt.plot(k_dist) → a curva dispara depois de ≈ 0.17–0.2

db = DBSCAN(eps=0.2, min_samples=5).fit(X)
labels = db.labels_                     # -1 = ruído
len(set(labels)) - (1 if -1 in labels else 0)   # 2 clusters
(labels == -1).sum()                    # 6 pontos de ruído
len(db.core_sample_indices_)            # 303 pontos core

10.4.3DBSCAN vs. K-means

Nas mesmas luas, o K-means com k = 2 tem ARI 0.254: corta cada lua ao meio com uma reta, porque para ele um cluster é uma "bola" à volta de uma média. O DBSCAN tem ARI 1.000 e ainda marca o ruído. Por outro lado, em grupos esféricos de densidades diferentes, o K-means costuma ganhar. Mais uma vez, a escolha depende da forma dos dados.

Clustering como classificação

Uma forma de testar um algoritmo de clustering é usá-lo num problema em que se conhece a classe, sem lha mostrar, e ver se os clusters coincidem com as classes. Por exemplo, separar universidades públicas de privadas, ou tumores benignos de malignos.

Exemplo: K-means com k = 2 no load_breast_cancer. O diagnóstico é retirado antes de agrupar e usado só para avaliar.

from sklearn.datasets import load_breast_cancer
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import classification_report

Xb, yb = load_breast_cancer(return_X_y=True); yb = 1 - yb        # 1 = maligno
for name, Z in [('sem normalizar', Xb), ('StandardScaler', StandardScaler().fit_transform(Xb))]:
    km = KMeans(n_clusters=2, n_init=10, random_state=42).fit(Z)
    pred = align(yb, km.labels_)
    print(name, accuracy_score(yb, pred), confusion_matrix(yb, pred))
AccuracyARIMatriz de confusão [[TN FP] [FN TP]]
Sem normalizar0.8540.491[[356 1] [82 130]]
StandardScaler0.9050.654[[339 18] [36 176]]

Sem normalizar, o clustering é dominado pela mean area e pela worst area (valores na casa das centenas ou milhares): basicamente separa os tumores "grandes" dos "outros", e falha 82 malignos. Normalizado, todas as features contam.

Quando corre bem, e quando corre mal
  • Bem: quando as classes formam grupos compactos e separados no espaço das features (normalizadas).
  • Mal: quando as classes se sobrepõem, quando há features irrelevantes ou em escalas diferentes que dominam a distância, ou quando a estrutura "natural" dos dados não corresponde às classes. O clustering encontra grupos, não necessariamente os grupos que nos interessam.
  • Como melhorar: normalizar, escolher ou reduzir features, testar outros algoritmos ou métricas de distância, e ajustar k ou ε.

Autoencoders

Um autoencoder (AE) é uma rede neuronal que aprende a comprimir (codificar) os dados até às suas características essenciais e depois a reconstruí-los (descodificar) a partir dessa representação. A entrada é também o alvo: não precisa de rótulos.

10.6.1Arquitetura

Encoder

Camadas que comprimem a entrada numa representação de menor dimensão.

Bottleneck (código)

A representação mais comprimida, ou espaço latente: é a saída do encoder e a entrada do decoder. Como tudo tem de passar por ali, a rede é obrigada a guardar só o essencial para reconstruir.

Decoder

Camadas cada vez maiores que reconstroem os dados na forma original. A diferença para a entrada é o erro de reconstrução.

Hiperparâmetros: o tamanho do código (quanto se comprime), o número de camadas, o número de nós por camada (diminui no encoder e aumenta no decoder) e a função de perda de reconstrução.

Há variantes para cada tipo de dados: denoising (limpar ruído de imagens ou som), variacionais (trabalham com distribuições em vez de valores fixos), convolucionais (imagens) e recorrentes (séries temporais e texto).

10.6.2Preparar os dados

  • Identificadores ficam de fora (um PassengerId, um número de cliente): não têm significado e só acrescentam ruído.
  • O target também fica de fora, mas guarda-se à parte para colorir o espaço latente depois.
  • Features muito assimétricas (como um preço) passam por \(\log(1+x)\).
  • Categorias nominais passam por one-hot, porque um código 0/1/2 inventaria uma ordem que não existe.
  • Tudo em [0, 1] com um MinMaxScaler ajustado só no treino. A última camada do decoder é uma sigmoide, por isso os alvos têm de estar nesse intervalo.
E se o teste sair de [0, 1]? complemento

Um scaler ajustado no treino pode dar valores abaixo de 0 ou acima de 1 no teste: aqui, 5 tumores do teste tinham alguma medida fora do intervalo do treino. A sigmoide nunca os consegue reproduzir. Uma solução simples é cortá-los com np.clip(..., 0, 1). E o próprio facto de saírem do intervalo já é um indício de que são invulgares.

10.6.3Treinar

import torch
from torch import nn
from sklearn.preprocessing import MinMaxScaler
from sklearn.model_selection import train_test_split

Xtr, Xte, ytr, yte = train_test_split(Xb, yb, test_size=0.3, random_state=42, stratify=yb)
mm = MinMaxScaler().fit(Xtr)
Ttr = torch.tensor(mm.transform(Xtr), dtype=torch.float32)
Tte = torch.tensor(np.clip(mm.transform(Xte), 0, 1), dtype=torch.float32)

class AE(nn.Module):
    def __init__(self, d, h1=16, h2=8, z=2):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(d, h1), nn.ReLU(), nn.Linear(h1, h2), nn.ReLU(), nn.Linear(h2, z))
        self.decoder = nn.Sequential(nn.Linear(z, h2), nn.ReLU(), nn.Linear(h2, h1), nn.ReLU(),
                                     nn.Linear(h1, d), nn.Sigmoid())      # saída em [0, 1]
    def forward(self, x):
        return self.decoder(self.encoder(x))

ae = AE(30)                                                  # 1328 parâmetros
loss_fn = nn.MSELoss()
opt = torch.optim.Adam(ae.parameters(), lr=1e-3, weight_decay=1e-5)
sched = torch.optim.lr_scheduler.StepLR(opt, step_size=10, gamma=0.95)   # lr × 0.95 a cada 10 épocas
loader = torch.utils.data.DataLoader(Ttr, batch_size=32, shuffle=True)

for epoch in range(150):
    for xb in loader:
        loss = loss_fn(ae(xb), xb)       # o alvo é a própria entrada
        opt.zero_grad(); loss.backward(); opt.step()
    sched.step()
época      1       10      50      150
treino  0.0965  0.0321  0.0098  0.0064
teste   0.0937  0.0301  0.0088  0.0059

Treino e teste andam juntos, por isso não há sinais de overfitting. O StepLR reduz o learning rate aos poucos, o que dá passos mais finos no fim do treino.

10.6.4A reconstrução

Com só 2 números por tumor, a rede reconstrói as 30 medidas com um erro pequeno, mas não igual para todas:

  • Mais fáceis: worst perimeter, worst area, worst radius (MSE ≈ 0.0008). Estão muito correlacionadas entre si, e um só número latente chega para as três.
  • Mais difíceis: worst texture, mean texture, texture error (MSE até 0.022). A textura varia de forma quase independente do tamanho e "não cabe" nos 2 números.

Nas unidades originais, para um tumor do teste: mean radius 14.53 → 14.75, mean area 659.7 → 680.3, worst concave points 0.096 → 0.103.

10.6.5O espaço latente

Cada tumor passa a ser descrito por 2 números, que se podem desenhar diretamente. Se o AE aprendeu algo útil, tumores parecidos ficam perto uns dos outros. Para o confirmar, colorem-se os pontos com informação que o AE nunca viu: o diagnóstico.

benignomaligno5 tumores do teste com maior erro de reconstrução

Os malignos e os benignos ocupam regiões diferentes, apesar de o diagnóstico nunca ter entrado no treino. Uma regressão logística treinada só com os 2 números latentes acerta 95.9% no teste. E o K-means com k = 2, aplicado aos pontos latentes do treino, encontra os dois grupos com 88.2% de acerto (ARI 0.577).

Gerar dados a partir do espaço latente

Pode alimentar-se o decoder com um ponto qualquer do espaço latente e ver que exemplo ele "imagina". Mas o espaço latente de um AE simples tem buracos entre grupos de pontos: a média de um grupo inteiro pode cair num desses buracos e dar um exemplo sem sentido. É melhor partir de um ponto real, como o exemplo mais próximo do centro do grupo. Andando aos poucos entre dois desses pontos, o exemplo gerado muda gradualmente de um para o outro.

10.6.6Detetar anomalias

O AE aprende a reconstruir bem o que é típico no treino. Exemplos invulgares são mal reconstruídos, por isso o erro de reconstrução serve de pontuação de anomalia.

with torch.no_grad():
    err = ((ae(Tte) - Tte) ** 2).mean(dim=1).numpy()     # erro por tumor
np.median(err)                       # 0.0043
np.argsort(err)[::-1][:5]            # os 5 piores: erro 0.040, 0.024, 0.022, 0.022, 0.021

Dos 5 tumores com maior erro, 4 são malignos (no teste, só 37% o são). Entre eles estão os extremos: um com área média de 2499 (a mediana é 551) e outro, o único benigno, com 244. O AE não sabe o que é "maligno", mas sabe o que é "normal" nos dados que viu.

Σ.2Armadilhas frequentes

  • Esquecer de normalizar: a feature com maior escala domina a distância.
  • Comparar números de clusters com classes sem alinhar: os números do clustering são arbitrários.
  • Escolher k só pela inércia: ela desce sempre quando k aumenta.
  • Usar o K-means em formas não convexas (luas, anéis): para isso existe o DBSCAN.
  • Um ε único para clusters de densidades muito diferentes: o DBSCAN parte uns e funde outros.
  • No autoencoder: ajustar o scaler aos dados todos, ou deixar o target ou identificadores na entrada.

Σ.3Perguntas de escolha múltipla

Qual é a diferença entre um centróide e um medoide?

O medoide é o ponto do cluster com menor soma de distâncias aos outros.

Juntaram-se alguns outliers muito afastados aos dados. Qual dos algoritmos é menos afetado?

O K-means usa médias e distâncias ao quadrado, por isso puxa um centro na direção dos outliers ou gasta um cluster com eles.

O K-means devolveu os rótulos [2, 2, 0, 1] e a verdade é [0, 0, 1, 2]. Qual é o ARI?

O ARI compara pares de pontos (juntos ou separados), não os números dos clusters.

Que métrica de clustering se pode usar sem rótulos verdadeiros?

A silhueta só usa as distâncias entre os pontos e os clusters a que foram atribuídos.

No DBSCAN, o que significa o rótulo −1?

Pontos longe de qualquer ponto core ficam como ruído. É assim que o DBSCAN deteta anomalias.

No DBSCAN, aumentar muito o ε faz com que…

Vizinhanças grandes ligam regiões que deviam estar separadas. Um ε pequeno demais faz o contrário: parte os clusters e cria muito ruído.

Os dados formam duas luas encaixadas. Que algoritmo as separa melhor?

K-means e K-medoids procuram grupos compactos à volta de um centro e cortam as luas com uma fronteira reta.

Num autoencoder, o que é o bottleneck?

Por ser estreito, obriga a rede a guardar só a informação essencial para reconstruir a entrada.

Como se usa um autoencoder para detetar anomalias?

O AE aprende o que é típico no treino; o que foge ao padrão é reconstruído com erro maior.

Σ.4Exercício

Com o load_wine (3 castas, 13 features), sem usar o rótulo para treinar:

  1. Aplica K-means, K-medoids e DBSCAN, com e sem normalização. Avalia cada um com o ARI, uma matriz de confusão (depois de alinhar) e um classification_report.
  2. Escolhe k pelo cotovelo e pela silhueta, e ε pelo gráfico de k-distâncias. Os critérios concordam com as 3 castas?
  3. Treina um autoencoder 13 → 8 → 2 → 8 → 13. As castas separam-se no espaço latente? Que vinhos têm o maior erro de reconstrução?
Pistas
  • Sem normalização, a prolina (centenas a milhares) domina as distâncias, e o resultado fica muito pior.
  • Com 13 dimensões, o ε não se lê "a olho": usa o gráfico de k-distâncias. Experimenta também reduzir primeiro a dimensão.
  • No AE, usa o MinMaxScaler ajustado ao treino, e uma sigmoide no fim do decoder.

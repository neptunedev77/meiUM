Virtualização: Máquinas VirtuaisVirtualization (Part I)

Virtualização é a técnica que cria um dispositivo ou recurso virtual, feito em software — na prática, uma abstração construída sobre recursos de hardware ou de software que já existem.

5.0.1Exemplos

Tipos de virtualização
  • Máquinas virtuais (VMs)
  • Redes virtuais
  • Memória virtual
  • Volumes lógicos de armazenamento
Na prática
  • Infraestruturas de desktops virtuais (VDI): os ambientes de trabalho dos utilizadores são servidos por um serviço central, ex.: VMs num cluster de servidores (VMware Horizon, Amazon WorkSpaces).
  • Cloud: os clientes recebem VMs que correm nos servidores do fornecedor (Amazon EC2, Google Compute Engine).

Vantagens da virtualizaçãoAdvantages

Quatro razões pelas quais a virtualização está em todo o lado.

5.1.1Heterogeneidade

O hardware é muito heterogéneo: modelos diferentes do mesmo tipo (CPU, GPU, RAM, disco, rede) podem ter interfaces e drivers diferentes. A virtualização esconde essa heterogeneidade e oferece recursos virtuais unificados — CPUs virtuais, discos virtuais, redes virtuais — com uma única interface, seja qual for o modelo físico por baixo.

5.1.2Transparência

Interagir com um recurso virtual é como interagir com um físico: ao fazer ssh para uma máquina remota, a experiência é igual quer seja uma VM quer seja um servidor bare-metal. Transparente quer dizer que o utilizador não precisa de mudar a forma de trabalhar (comandos, programas, scripts).

5.1.3Isolamento

Recursos virtuais que partilham um recurso físico têm de estar isolados:

Segurança

A VM de um utilizador não pode aceder à memória das VMs de outros — isso permitiria ataques e corrupção de memória.

Desempenho

A VM de um utilizador não deve prejudicar o desempenho das outras que partilham CPU, memória, disco e rede.

Falhas

A falha de uma VM não deve fazer falhar as outras VMs do mesmo host.

5.1.4Consolidação e gestão

  • Consolidar os recursos físicos baixa os custos e aproveita melhor o hardware: um só servidor pode correr, por exemplo, vários sistemas operativos em VMs.
  • Gerir recursos virtuais é mais fácil e flexível: as VMs criam-se, destroem-se e migram mais depressa do que servidores físicos.

Desvantagens da virtualizaçãoDisadvantages

A camada extra de abstração tem custos.

Desempenho e sobrealocação
  • A virtualização costuma acrescentar uma penalização de desempenho: os mecanismos que abstraem o hardware têm trabalho extra a mediar cada pedido virtual até ao hardware real.
  • Pôr demasiados recursos virtuais sobre o mesmo hardware leva a sobrealocação (over-provisioning) e degradação: quando várias VMs no mesmo servidor pedem mais núcleos, memória ou largura de banda do que existe.
Segurança e fiabilidade
  • Se o isolamento falhar, ou se alguém malicioso tiver acesso privilegiado ao recurso físico, todos os recursos virtuais ficam comprometidos — ex.: um administrador com root no servidor pode comprometer todas as VMs.
  • A falha de um recurso físico compromete todos os virtuais que o usam: se o servidor avariar, todas as VMs que lá correm caem.
Não é só sobre VMs

Estas vantagens e desvantagens valem para os vários tipos de virtualização — memória, rede, armazenamento — não só para VMs. Exercício: confirma cada propriedade para a memória virtual (ex.: o isolamento é o que impede um processo de ler a memória de outro).

Máquinas virtuaisVirtual Machines

Uma máquina virtual permite correr vários sistemas operativos sobre o mesmo servidor físico.

5.3.1Contexto

  • Os mainframes da IBM, há cerca de 50 anos, já permitiam às aplicações usar porções isoladas dos recursos do sistema.
  • A virtualização massificou-se no início dos anos 2000, com os servidores x86, por causa do custo da infraestrutura (servidores caros) e dos recursos subaproveitados (servidores longe da sua capacidade máxima).
  • Além disso, adaptar uma aplicação para correr noutro sistema operativo é caro e difícil — com VMs, corre-se o SO de que ela precisa.

5.3.2Arquitetura

As instruções do SO convidado (a VM) são intercetadas, traduzidas e executadas no SO e hardware do host.

5.3.3O hypervisor

  • Também chamado Virtual Machine Monitor (VMM). Exemplos: Xen, KVM, VMware, VirtualBox.
  • Controla a interação de baixo nível entre as VMs e o SO e hardware do host: dá acesso ao CPU, à RAM, ao disco e à rede do host.

Mas como é que os recursos físicos são partilhados entre as VMs? É o assunto da sub-página seguinte.

Como as VMs partilham o hostHost's CPU · RAM · Storage · Network

Cada tipo de recurso é partilhado de forma diferente.

5.4.1CPU: time slicing

  • O tempo de processamento é fatiado e repartido entre as VMs — como vários processos num SO (as aulas de Sistemas Operativos).
  • Cuidado: atribuir mais vCPUs do que os núcleos existentes (overcommit) pode levar a mau desempenho.

5.4.2RAM e armazenamento persistente

  • Cada VM fica com uma porção específica da RAM e da capacidade de armazenamento (SSD, HDD) do host.
  • A gestão de memória usa sobretudo os mecanismos tradicionais dos SO: paginação, TLB (Translation Lookaside Buffer)…
  • O armazenamento persistente é partilhado entre VMs: tem de lidar bem com vários leitores e escritores, e pode ser atribuído à medida que é preciso (thin provisioning).
Complemento · thin provisioning

Uma VM pode "ver" um disco de 100 GB que, no host, só ocupa o espaço realmente escrito (ex.: 8 GB). Poupa espaço, mas se todas as VMs encherem os seus discos ao mesmo tempo o host pode ficar sem espaço — é outra forma de sobrealocação.

5.4.3Rede

As VMs partilham a largura de banda do host e podem ter diferentes configurações de rede:

ModoComo funcionaA VM consegue chegar a…
Host-onlyPartilha o espaço de rede do hostSó ao host
NATO tráfego da VM sai como se fosse do host (uma só identidade de rede)Recursos externos (mas não é diretamente visível de fora)

Modos e tipos de virtualizaçãoVirtualization Modes · Types

Duas classificações independentes: como o SO convidado é virtualizado (modo) e onde corre o hypervisor (tipo).

5.5.1Modos

Virtualização completaParavirtualização
IdeiaO SO convidado é totalmente abstraído do hardware do hostO SO convidado tem modificações (hooks) para evitar a tradução das instruções mais caras
ExemploVirtualBoxXen
VantagemSem alterar o SO: mais sistemas suportados e VMs mais fáceis de migrar/portarMelhor desempenho de CPU e I/O (menos tradução)
DesvantagemTodas as instruções têm de ser traduzidas pelo hypervisor: CPU e I/O potencialmente mais lentosO SO tem de ser modificado: pior manutenção e portabilidade (imagens de SO modificadas)
Virtualização assistida por hardware

Extensões do processador como Intel VT-x e AMD-V reduzem a penalização da tradução de instruções na virtualização completa — o hardware ajuda o hypervisor.

5.5.2Tipos de hypervisor

Tipo 1 · bare metal
  • Não precisa de um SO de uso geral no host: é instalado diretamente no hardware, como um "pequeno sistema operativo".
  • Bom desempenho (o pequeno SO é otimizado para virtualizar), mas costuma exigir suporte de virtualização no hardware.
  • Ex.: VMware ESX.
Tipo 2 · hosted
  • Instalado por cima de um SO de uso geral; muitos ainda exigem módulos de kernel específicos.
  • Pior desempenho: o SO não está otimizado para virtualizar.
  • Ex.: VirtualBox.
Classificações que variam

O Xen e o KVM aparecem classificados de formas diferentes consoante a fonte. O Xen corre diretamente sobre o hardware (com um domínio privilegiado, o Dom0, para gerir dispositivos), por isso é muitas vezes descrito como tipo 1. O KVM é um módulo que transforma o próprio kernel Linux num hypervisor — corre "dentro" de um SO de uso geral, mas com acesso direto ao hardware. Em exame, justifica a classificação pelo critério: há ou não um SO de uso geral por baixo do hypervisor?

Σ.2Perguntas de escolha múltipla

A VM de um cliente está a usar 100% do CPU e as VMs de outros clientes no mesmo host não abrandam. Que propriedade é esta?

O isolamento garante que uma VM não prejudica o desempenho, a segurança ou a disponibilidade das outras.

Um servidor com 16 núcleos corre VMs com um total de 40 vCPUs. O que pode acontecer?

Overcommit de CPU: funciona enquanto a procura real for baixa; com carga simultânea, há degradação.

Queres que a VM seja vista na rede física com o seu próprio IP. Que modo usas?

Em bridge a VM é mais um nó da rede; em NAT o tráfego sai com a identidade do host.

Qual é a principal desvantagem da paravirtualização?

Ganha desempenho evitando traduções caras, mas à custa de imagens de SO modificadas.

O que distingue um hypervisor de tipo 1?

Tipo 1 = bare metal (ex.: VMware ESX); tipo 2 = sobre um SO de uso geral (ex.: VirtualBox).

Para que servem o Intel VT-x e o AMD-V?

Virtualização assistida por hardware.

Os serviços de cloud dividem-se em três grandes abstrações, consoante quanto da pilha fica a cargo do fornecedor: IaaS (infraestrutura), PaaS (plataforma) e SaaS (software).

Infrastructure-as-a-ServiceIaaS

O fornecedor tem os data centers; tu alugas os recursos de que precisas, quando precisas.

4.1.1A infraestrutura

  • Data centers espalhados pelo mundo (Ásia, Europa, América).
  • Cada um com cerca de 80 000 servidores.
  • Principais fornecedores: Google, Amazon e Microsoft.

4.1.2Objetivos

  • Fornecer recursos de hardware virtualizados: computação, armazenamento e rede.
  • Recursos atribuídos a pedido (on demand: quando o utilizador os pede) e em regime de pagamento por uso (pay-per-use: só se paga o que se usa de facto).
Computação

Amazon EC2, Google Compute Engine

Armazenamento

Amazon S3

Um exemplo de IaaS: OpenStackOpenStack

Software open-source para criar clouds privadas e públicas. Controla grandes conjuntos de recursos de computação, armazenamento e rede num data center, geridos por um dashboard ou pela API do OpenStack. Cada função é um serviço com nome próprio.

4.2.1Computação: Nova

O Nova fornece diferentes tipos de instâncias de computação: servidores bare-metal, máquinas virtuais e containers. Para isso integra-se com outros serviços:

ServiçoFunção
KeystoneIdentidade e autenticação
GlanceRepositório de imagens (ex.: imagens de VMs)
NeutronRedes virtuais ou físicas para as instâncias
PlacementRegista os recursos de hardware disponíveis e atribui-os (ex.: ao criar uma VM)

4.2.2Armazenamento: efémero, Cinder, Manila, Swift

As instâncias têm armazenamento efémero, dado pelo Nova e apagado quando a instância termina. Para armazenamento persistente há três serviços:

Cinder · blocos

Volumes que aparecem à VM como um disco (ex.: /dev/vdc), que se particiona, formata e monta.

Manila · ficheiros

Sistemas de ficheiros partilhados entre instâncias, como um NFS.

Swift · objetos

API chave-valor (imagina um hash map distribuído), ideal para dados não estruturados — vídeos, imagens. Muito escalável e fiável.

4.2.3Rede e monitorização: Neutron e Telemetry

  • Neutron: fornece rede como serviço (NaaS) aos ambientes virtuais. Segue os princípios de Software-Defined Networking (SDN): separa o encaminhamento dos pacotes das decisões de routing.
  • Telemetry: monitorização da infraestrutura e dos recursos virtuais. Recolhe métricas de recursos físicos e virtuais, guarda-as para análise e dispara ações quando se cumprem regras — por exemplo, lançar mais VMs quando o CPU passa um limiar.

Platform-as-a-ServicePaaS

O utilizador escreve uma aplicação e faz deploy dela; a plataforma garante que a aplicação corre e tem acesso aos recursos de que precisa.

4.3.1Diferenças em relação ao IaaS

  • O utilizador concentra-se na funcionalidade a disponibilizar, não nos recursos físicos ou virtuais que a suportam.
  • Os recursos tornam-se transparentes — o utilizador não precisa de saber em que hardware a aplicação corre — e a aplicação passa a ser a unidade de deployment.
  • Oferece um ambiente de desenvolvimento para desenvolver, instalar e correr aplicações: normalmente um ambiente de programação com várias linguagens (Python, Java…) e APIs para usar outros serviços da cloud.

4.3.2Exemplo: Google App Engine

  • Baseado em instâncias de containers.
  • Várias linguagens (Java, Python, PHP…), ferramentas (Cloud SDK, IntelliJ IDEA…) e APIs (Google Cloud Storage…).
  • Funcionalidades de versionamento, testes, monitorização e logging.

Software-as-a-ServiceSaaS

Aplicações completas ou software genérico oferecidos como serviço. A aplicação do utilizador usa o serviço através de uma API — e nem precisa de correr na mesma plataforma.

  • Alguns são componentes de software que exportam as suas APIs tradicionais.
  • Outros são acessíveis como serviços web ou pelo browser.
Bases de dados

Não há nada para instalar: a base de dados é usada através de um cliente, como uma tradicional, mas com configuração mínima e acesso remoto. Ex.: Amazon DynamoDB.

Aplicações web

Salesforce e as Google Apps (Gmail…).

IA e análise de dados

Plataformas como o Amazon SageMaker.

Gerir (tarefa do fornecedor) e usar (tarefa do utilizador) estes serviços exige perceber muitos conceitos e tecnologias: sistemas distribuídos, virtualização, redes, armazenamento, provisionamento, monitorização, relatórios, faturação… e a interoperabilidade entre tudo isto.

Subir de IaaS para PaaS e para SaaS dá cada vez mais conveniência — e tira cada vez mais controlo.

Elasticidade

Capacidade de aumentar ou reduzir recursos (computação, armazenamento, rede) e/ou componentes (bases de dados, aplicações, servidores web) conforme as necessidades da aplicação. Junto com o pagamento por uso, é o que permite pagar pouco quando há pouca procura e aguentar picos.

4.5.2Desvantagens

Perda de controlo
IaaSSem controlo sobre o hardware e o software de virtualização: não há como afinar a infraestrutura para a aplicação.
PaaSSem controlo sobre o hardware nem sobre a plataforma: gestão, afinação e monitorização limitadas às ferramentas oferecidas.
SaaSSoftware de terceiros, otimizado e configurado sobretudo pelo fornecedor.
Fiabilidade

Se o fornecedor falhar (mesmo que raramente), a aplicação falha, e a recuperação está fora do controlo do dono da aplicação.

Segurança

A aplicação é, no máximo, tão segura como o fornecedor: uma vulnerabilidade dele é uma vulnerabilidade dela, e só ele a pode corrigir.

Privacidade

O fornecedor guarda os dados dos utilizadores: risco de fugas por ataques externos ou internos. Há dados protegidos por lei (RGPD, HIPAA) que algumas instituições — como hospitais — não podem guardar em serviços de terceiros.

Σ.2Perguntas de escolha múltipla

Alugas uma VM e instalas lá o SO, a base de dados e a aplicação. É…

Recebes infraestrutura virtualizada e geres tudo a partir do sistema operativo.

No Google App Engine, qual é a unidade de deployment?

É PaaS: os recursos são transparentes e entrega-se o código da aplicação.

Que tipo de armazenamento do OpenStack desaparece quando a instância termina?

Cinder e Swift persistem até o utilizador os apagar.

Precisas de guardar dezenas de TB de vídeos acessíveis de qualquer lado por HTTP. Qual escolhes?

Armazenamento de objetos: API REST, acessível de qualquer lado, muito escalável. Equivale ao S3.

Qual é o equivalente AWS do Cinder?

Cinder ↔ EBS (blocos); Swift ↔ S3 (objetos); Telemetry ↔ CloudWatch.

Um hospital não pode guardar dados clínicos num SaaS de terceiros. Que desvantagem da cloud é esta?

Legislação como o RGPD ou a HIPAA pode impedir o uso de serviços de terceiros.
